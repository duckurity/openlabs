## Ways to contribute

Author a lab. Fix an existing lab. Improve the docs. Report a broken lab through the issue forms.

## Author a lab

Copy `labs/_template/` into `labs/<track>/<lab-name>/`. Fill in the metadata. Write the brief. Build the service. Run the validator:

```bash
python3 scripts/validate.py
```

Open a pull request. Keep one lab per pull request.

## Lab metadata

`lab.yml` holds flat YAML, one `key: value` per line:

| Key | Rules |
|---|---|
| `name` | matches the directory name, lowercase, hyphens |
| `track` | one of `web`, `binary`, `crypto`, `network`, `osint` |
| `difficulty` | one of `easy`, `medium`, `hard`, `insane` |
| `description` | one line, shown in the lab index |
| `flag_hash` | SHA-256 of the full flag string, `64` lowercase hex |

Compute the hash from the exact flag string, braces included:

```bash
printf '%s' 'duck{your_flag_here}' | sha256sum
```

## Rules for labs

Keep the service self-contained. Run offline once images are pulled. Place no runtime calls to external services.

Pin base images to a full version tag. Use `python:3.12-alpine`. Never use `python:latest`.

Generate each flag body randomly. Ship one flag per lab. Never reuse a flag. Keep plaintext flags inside lab internals. Store the hash in `lab.yml`.

Expose one documented host port per lab. State the port in the brief and in `docker-compose.yml`.

Write the brief in the repo voice. Use short declarative sentences. Use sentence case for headings.

## Difficulty rubric

Grade against what a player does. Ignore how long it takes:

| Level | Expectation |
|---|---|
| `easy` | one clear vector, minimal recon, the brief points at the surface |
| `medium` | chained steps, some enumeration, the vector needs a decision |
| `hard` | multiple systems or stages, custom tooling, dead ends that punish assumptions |
| `insane` | research-level, an original technique, no public reference walkthrough |

Pick one tier. Grade down when a lab sits between two. Let the solve rate correct it later.

## Review

Review covers structure, difficulty accuracy, voice, and clean-clone runs. CI runs the same validator. Keep every check green before review.
