## Overview
An Android application that loads untrusted HTML into a WebView must carefully constrain JavaScript execution and any native interfaces exposed to that content.

## Examples
Look for WebViews that enable JavaScript and expose native methods through interfaces such as `addJavascriptInterface`. Check whether untrusted pages, redirects, or externally controlled content can reach those methods. Review the bridge methods and determine what data or functionality they expose.

## FAQ

**Does every JavaScript-enabled WebView have this vulnerability?**
No. Enabling JavaScript alone does not establish a bridge exposure. The risk depends on the native interfaces exposed, the content loaded, and the trust boundaries enforced by the application.

**Does JavaScript bridge exposure automatically mean remote code execution?**
No. The impact depends on the methods exposed by the bridge and the actions they permit. Access to native functionality does not automatically imply operating-system command execution.

**How can I practise testing this issue?**
Inspect the WebView configuration, identify exposed JavaScript interfaces, and determine whether untrusted content can invoke them. Start with the [DuckWebView lab](/labs/duckwebview) and read [how to play](/play) for the challenge workflow.
