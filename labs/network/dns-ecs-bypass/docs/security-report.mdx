# Security report — dns-ecs-bypass

## Isolation

- Single container, no host network mode, one published UDP port
  (`127.0.0.1:5353:5353/udp`).
- Dedicated bridge network, static subnet `10.10.10.0/24`, no other
  services attached.
- No outbound DNS forwarding or recursion — the server answers only from
  its own fixed zone table, never queries upstream.
- Container runs as unprivileged `USER 65534`, no capabilities added.

## Flag handling

- Plaintext flag exists only inside `src/dns_server.py`, inside the lab
  directory.
- `lab.yml` carries only `flag_hash` (SHA-256).
- No flag material in `README.md`, this `docs/` folder, or any file outside
  `labs/network/dns-ecs-bypass/`.

## Attack surface beyond the intended vector

- The server parses raw DNS packets by hand (question section, OPT/ECS
  option). Input is attacker-controlled UDP payloads up to 1024 bytes.
  Malformed packets are caught by a broad `except Exception` around the
  per-packet handling loop so one bad packet cannot crash the listener.
- No filesystem writes, no shell execution, no subprocess calls anywhere in
  the service code.
- Base image pinned to a digest
  (`python:3.12-slim@sha256:aa943ce411423c7582288f18707ff66eddcbaeb510502d747a72aeb34f30d159`)
  to avoid silent upstream drift.

## Known limitations

- The hand-rolled DNS parser is intentionally minimal and not a general
  purpose resolver; it is not intended to be reused outside this lab.
