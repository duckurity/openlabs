## Reproduction

From the repository root, run the structural and Compose validators:

```sh
python -B scripts/validate.py
python -B scripts/validate.py --compose
```

From the lab directory, build the test target and run the suite in the restricted container. Before running these raw Docker commands, confirm that the active Docker context targets the intended local engine and that `DOCKER_HOST`, `DOCKER_CONTEXT`, and `COMPOSE_*` overrides are unset. The raw Docker CLI does not enforce the scope checks performed by the Python helpers.

```sh
docker build --network=default --target test --tag sealdesk:test .
docker run --rm --network=none --read-only --user 10001:10001 \
  --cap-drop ALL --security-opt no-new-privileges:true \
  --memory 256m --memory-swap 256m --cpus 1 --pids-limit 64 \
  --tmpfs /tmp:rw,noexec,nosuid,nodev,size=16m,uid=10001,gid=10001,mode=0700 \
  --entrypoint python sealdesk:test -B -m unittest discover -s tests -v
```

To reproduce the local lifecycle from the lab directory:

Before running these raw Compose commands, follow the context and override check in the [operations runbook](operations.mdx).

```sh
docker compose up -d --build --wait
python scripts/sync_flag_hash.py
docker compose ps
python solver/solve.py --url http://127.0.0.1:8080
python reset.py
python solver/solve.py --url http://127.0.0.1:8080
docker compose down
```

The solver passes the returned flag to the repository checker in memory and does not print it. For a manual checker exercise, use `python ../../../scripts/check.py .` and enter a test value only at the prompt. The [official solution](official-solution.mdx) describes the player workflow. The test image build may need internet access for the pinned base and wheels. The test container itself has no network. Use `python3` where the host does not provide `python`.

The recorded Dockerfile checks used `docker build --check` for `Dockerfile` and `Dockerfile.ingress`. The strict challenge-sheet check used the repository's canonical PDF generator. The strict SEO check used `contentbit doctor --strict-seo`. The local link result covers local paths and heading anchors only. These commands reproduce their respective checks; they do not substitute for hosted CI.

## Independent playtest procedure

This procedure describes a separate source-blind assessment. It does not describe or relabel the completed author-run playtest. If a separate assessment is conducted, provide only a service-only package and the player README. Do not provide this document set, the evaluator solver, source code, or runtime filesystem access. The reviewer should not receive coaching during the solve.

Record the following:

- Whether clean deployment from the player README succeeds, including setup friction.
- What response evidence led the reviewer to identify the oracle.
- Whether the reviewer recovered the required code and submitted the final flag.
- Any hints used and whether they changed the intended learning objective.
- Reset and stale-value rejection results.
- Any ambiguity, unintended shortcut, or non-obvious failure.
- The reviewer's own difficulty assessment and the basis for it.

An independent reviewer can provide separate difficulty evidence. The author-run result recorded below cannot provide that evidence. The procedure is guidance, not a release-status claim.
