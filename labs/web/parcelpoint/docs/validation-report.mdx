## Validation coverage

The current 34-test application suite covers:

- public locker listing and detail privacy, health responses, security headers, JSON errors, and request limits;
- customer registration, login, profile, logout, and session behavior;
- reset-code delivery, ownership, expiry, single-use consumption, session revocation, unregistered-target recovery, and the intentionally vulnerable target binding;
- UI and OpenAPI input limits and request-schema accuracy;
- public OpenAPI discovery through the homepage response header and absence of the API explorer from the application UI;
- deterministic Jules-to-Mira escalation, courier roles, route assignments, held-locker checks, and both solver stages;
- seed fixtures, digest-only checker metadata, database handling, operator ownership checks, and reset rotation;
- frontend labels, ARIA references, CSP-compatible markup, local assets, and text-only rendering.

| Scope | Coverage limit |
|---|---|
| Application tests | Evidence for intended flows and selected negative cases; not proof against every unintended behavior |
| Docker images | Built from this candidate with both builders; base layers came from the local digest-pinned image rather than a fresh registry download |
| Live runtime | Two clean-export lifecycle runs on Windows and WSL; not a long-running or multi-user deployment |
| Reset-code boundaries | Normal, invalid, expired, and consumed codes are covered; no production-grade rate limit is established |
| Ingress | Ordinary forwarding is exercised by every live request; no proxy concurrency or half-close test is claimed |
| Isolation | Container identity, capabilities, read-only roots, published ports, and application egress were inspected live; no host or kernel escape assurance is claimed |
| Load and abuse resistance | Registration, reset, mailbox growth, and concurrent requests were not stress-tested |
| Accessibility | Structural frontend tests only; no full WCAG, keyboard-only, screen-reader, or cross-browser review |
| Supply chain | Base image pinned by digest and wheels pinned by hash; the Scout scan is a point-in-time result for the candidate images |
| Independent acceptance | The human playtest was run by the challenge author; it is not replaced by the bundled solver, and maintainer review may add an independent pass |

## Reproduction

From the repository root:

```text
python3 scripts/validate.py --compose
python3 scripts/score_lab.py labs/web/parcelpoint --min 70
python3 scripts/make_lab_pdf.py labs/web/parcelpoint --strict
```

The PDF must be generated through the repository script; do not invoke LaTeX directly. Inspect the generated sheet for clipping and spoiler content. On native Windows, pass `score_lab.py` an absolute path such as `D:/path/to/openlabs/labs/web/parcelpoint`.

From `labs/web/parcelpoint`:

```text
docker compose --profile test run --build --rm tests
docker compose up -d --build --wait
python3 scripts/sync_flag_hash.py
python3 solver/solve.py
python3 reset.py
python3 solver/solve.py
docker compose down
```

The first build requires access to the pinned base image and hash-pinned Python wheels. The Compose test service has no network, uses a read-only root and UID `10001:10001`, and runs tests baked into the `test` target. Use `--build` so the command cannot silently test an older image. The evaluator solver passes captured flags to the shared checker in memory and prints no flag. The manual recovery path is in the spoiler-marked [official solution](official-solution.mdx).
